# Ruvo — AI ভিডিও স্টুডিও

চরিত্র একবার বানাও, তারপর যত দৃশ্য, যত এপিসোড বানাও, সবখানে চেহারা এক থাকবে। ভিডিও আর ছবি বানায় Google-এর Gemini API (AI Studio key)।

কোনো বাইরের প্যাকেজ লাগে না। Node 22.13 বা নতুন হলেই চলবে। (PostgreSQL ব্যবহার করলে শুধু `pg` লাগে, `npm ci` দিলেই আসে।)

ভেতরের কাঠামো, নিরাপত্তা আর অনেক ব্যবহারকারীর জন্য কী লাগবে: [ARCHITECTURE.md](ARCHITECTURE.md)।

## চালু করার ধাপ

> **সবচেয়ে সহজ পথ: [DEPLOY.md](DEPLOY.md)** (Render, এক চাপে, কোনো সেটিং ছাড়া)। নিচেরটা বিস্তারিত।

### ১. Gemini API key
1. aistudio.google.com-এ যাও → **Get API key** → একটি key বানাও।
2. ভিডিও বানাতে বিলিং লাগে, কারণ Omni Flash-এর কোনো ফ্রি টিয়ার নেই। key-টি যে Google Cloud প্রজেক্টের, সেখানে বিলিং চালু করো। তাহলে তোমার $300 ক্রেডিট থেকে খরচ যাবে।
3. Cloud Console → **Billing → Budgets & alerts**-এ একটি বাজেট সতর্কতা বসাও।

### ২. Gmail লগইন
1. console.cloud.google.com → **APIs & Services → OAuth consent screen** → External → অ্যাপের নাম "Ruvo" আর তোমার ইমেইল দিয়ে সেভ করো, তারপর **Publish app** চাপো।
2. **Credentials → Create credentials → OAuth client ID → Web application**।
3. **Authorized JavaScript origins**-এ অ্যাপের ঠিকানা দাও, যেমন `https://ruvo.up.railway.app`। নিজের কম্পিউটারে পরীক্ষার জন্য `http://localhost:3200`।
4. যে Client ID পাবে, সেটা `GOOGLE_CLIENT_ID`-এ বসাও।

### ৩. নিজের কম্পিউটারে চালানো
```
cd ruvo
cp .env.example .env      # GEMINI_API_KEY, GOOGLE_CLIENT_ID, OWNER_EMAIL বসাও
npm start                 # http://localhost:3200
```
Gmail ছাড়া পরীক্ষা করতে `.env`-এ `DEV_LOGIN=1` দাও। আসল সার্ভারে এটা কখনো চালু রাখবে না।

### ৪. অনলাইনে তোলা (Railway)
1. railway.com → **New Project → Deploy from GitHub repo** → এই রিপো।
2. **Settings → Root Directory**: `ruvo`।
3. **Volume** যোগ করো, Mount path `/data`। ভিডিও আর ডেটা এখানে থাকে। Volume না দিলে প্রতিটি আপডেটে সব মুছে যাবে।
4. **Variables**: `GEMINI_API_KEY`, `GOOGLE_CLIENT_ID`, `OWNER_EMAIL`, `PUBLIC_URL`, `DATA_DIR=/data`।
5. **Networking → Generate Domain**। সেই ঠিকানা OAuth-এর Authorized JavaScript origins-এ যোগ করো।

Google Cloud Run-এও চালানো যায়, তবে Cloud Run-এর ডিস্ক স্থায়ী নয়। তখন ভিডিও রাখার জন্য Cloud Storage যোগ করতে হবে।

### ৪খ. GitHub Actions দিয়ে নিজে থেকে চালু (প্রস্তাবিত)
রিপোতে `.github/workflows/ruvo.yml` আছে। প্রতিবার কোড পুশ করলে আগে সব পরীক্ষা চলে, পাস করলে Railway-তে নতুন ভার্সন চালু হয়। পরীক্ষা ফেল করলে চালু হয় না, তাই ভাঙা কোড অনলাইনে যায় না।

একবার সেটআপ:
1. railway.com → **New Project → Empty Project** → **+ Create → Empty Service**। (GitHub রিপো জোড়া লাগবে না, Actions নিজেই কোড পাঠাবে। Root Directory-ও লাগবে না।)
2. সার্ভিসে **Volume** যোগ করো, Mount path `/data`।
3. সার্ভিসের **Variables**-এ উপরের ৪ নম্বর ধাপের Variables বসাও (`GEMINI_API_KEY`, `GOOGLE_CLIENT_ID`, `OWNER_EMAIL`, `PUBLIC_URL`)। `DATA_DIR` আর Node-এর ভার্সন Dockerfile-এ বসানো আছে।
4. **Settings → Networking → Generate Domain**, ঠিকানাটা `PUBLIC_URL`-এ আর OAuth-এর Authorized JavaScript origins-এ দাও।
5. প্রজেক্টের **Settings → Tokens → Create Token** (Project token)। টোকেন কপি করো।
6. সার্ভিসে ক্লিক করে **Settings**-এ Service ID কপি করো।
7. GitHub-এ রিপো → **Settings → Secrets and variables → Actions**:
   - **Secrets** ট্যাবে `RAILWAY_TOKEN` = ধাপ ৫-এর টোকেন
   - **Variables** ট্যাবে `RAILWAY_SERVICE_ID` = ধাপ ৬-এর আইডি
8. রিপোর **Actions → Ruvo — পরীক্ষা ও চালু → Run workflow**। সবুজ ✓ হলে অ্যাপ চালু।

এরপর থেকে `ruvo/` ফোল্ডারে কিছু বদলে পুশ করলেই নিজে থেকে নতুন ভার্সন চালু হবে।

### ৫. মালিকের কন্ট্রোল প্যানেল চালু করা
1. সার্ভারের **Variables**-এ (Railway → সার্ভিস → Variables) `OWNER_PANEL_PASSWORD` = তোমার পাসওয়ার্ড বসাও। বেশি নিরাপদ চাইলে `npm run panel-hash` চালিয়ে যে হ্যাশ পাবে সেটা `OWNER_PANEL_PASSWORD_HASH`-এ বসাও।
2. পাসওয়ার্ড কোডে, GitHub-এ বা ডেটাবেসে কোথাও থাকে না, আর অ্যাপের ভেতর থেকে বদলানোর কোনো রাস্তা নেই। বদলাতে হলে Variables-এ বদলাও।
3. অ্যাপে মালিকের Gmail দিয়ে ঢুকে পাশের মেনু (বা ＋) → **🔐 মালিকের কন্ট্রোল** → পাসওয়ার্ড।
4. ভেতরে **📞 যোগাযোগের তথ্য**-এ নিজের WhatsApp/ফোন/Facebook বসাও। এগুলো সবাই "সাহায্য ও যোগাযোগ" আর লগইন পাতায় দেখবে।

### ৬. অন্যদের ঢুকতে দেওয়া
তুমি বা তোমার অ্যাডমিন: **🛡️ অ্যাডমিন → কারা ঢুকতে পারবে** → Gmail যোগ করো। কাউকে সরানো, ব্লক বা কিক করা শুধু মালিকের কন্ট্রোল প্যানেল থেকে। অন্যদের দৈনিক সীমা `.env`-এর `DAILY_VIDEO_LIMIT` আর `DAILY_IMAGE_LIMIT` দিয়ে ঠিক হয়। মালিকের কোনো সীমা নেই।

## সীমাবদ্ধতা
- Gemini সার্ভারে তৈরি ভিডিও বাড়ানো বা বদলানো যায় নির্দিষ্ট সময় পর্যন্ত (পেইড টিয়ারে ৫৫ দিন, ফ্রি টিয়ারে ১ দিন)। এরপর "বাড়াও" আর "বদলাও" কাজ নাও করতে পারে। ফাইল তোমার সার্ভারে থেকে যায়।
- দৃশ্যক্রমের ক্লিপগুলো এক ফাইলে জোড়া লাগায় না। ক্লিপ ডাউনলোড করে CapCut-এর মতো এডিটরে জোড়া দাও।
- আসল মানুষের ছবি দিয়ে ভিডিও বানানো Google-এর নিয়মে আটকে যেতে পারে।
- কাজ বাতিল করলেও, Google-এ পাঠানো হয়ে গিয়ে থাকলে Google খরচ ধরতে পারে।
- খরচ শুধু আনুমানিক। আসল বিল Google Cloud Billing-এ দেখো।
- Google-এর লেখার মডেল ব্যস্ত থাকলে উত্তর আসতে আধা মিনিটেরও বেশি লাগতে পারে। দ্রুত চাইলে `TEXT_MODEL=gemini-3.5-flash-lite` দাও।

```
npm run test:all        # ইউনিট + পুরো API + কঠিন পরিস্থিতি (নকল Gemini, খরচ নেই)
npm run test:ui         # আসল ব্রাউজারে (Playwright লাগে)
GEMINI_API_KEY=... npm run test:real   # আসল Gemini-তে ছোট যাচাই (সামান্য খরচ)
```
নকল Gemini দিয়ে চলা পরীক্ষায় key বা টাকা লাগে না। কোন পরীক্ষা আসল API-তে আর কোনটা নকলে, তার তালিকা ARCHITECTURE.md-তে।
